## 2025-06-08 - [CRITICAL] Memory Leak and IP Spoofing in API Rate Limiter
**Vulnerability:** The in-memory rate limiter for the `/api/contact` endpoint used an unbounded `Map` (`RATE_LIMIT`) that was never cleaned up. Additionally, the IP address extraction was vulnerable to IP spoofing because it trusted the first IP in `x-forwarded-for` (which can be easily forged by a client) instead of using the most trusted proxy IP or `x-real-ip`.
**Learning:** In-memory maps for rate limiting must always have an eviction policy or size limit to prevent Out-Of-Memory (OOM) Denial of Service attacks. Also, when parsing `x-forwarded-for`, untrusted proxies can inject arbitrary IPs at the beginning of the list, so relying on `.split(',')[0]` allows attackers to bypass rate limits by sending a fake IP on each request.
**Prevention:** Use an established rate limiting library (like `upstash/ratelimit`) or implement bounds checking (e.g., clearing the Map when it exceeds a threshold size). Extract IPs securely by checking `x-real-ip` or the last IP in the `x-forwarded-for` chain, which is typically set by the immediate proxy/load balancer.
